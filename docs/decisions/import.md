# Import decisions

Decisions made while building the Toggl CSV import (`src/import/`), for the owner's review.
The owner-facing description is in `docs/import.md`.

| Decision | Why | How to change it |
| --- | --- | --- |
| The input is the Detailed report **CSV**; columns are matched by heading, case-insensitively, in any order, with extra or missing columns tolerated. Only a start and some way to know the length (end or duration) are required | No sample file was available, so the importer cannot rely on one exact layout. Toggl has changed its export columns over the years | `HEADER_NAMES` and `mapHeaders` in `toggl.ts` |
| Times have no offset in the export, so the person picks the **time zone** in the preview (default: the browser's). Wall-clock times are converted with `Intl`, no library | The export is in the exporting user's zone, which may differ from this browser's. Changing the zone re-plans without re-reading the file | `zone.ts`; add a remembered zone if wanted |
| A clock that repeats an hour is resolved with the **Duration** column (the candidate closest to start + duration); a time that does not exist moves forward as the platform does. A start and end that disagree with Duration by more than a minute give a warning | Toggl's duration is real elapsed time, so the stored length stays right on clock-change nights and a wrong zone is noticed | `parseRow` in `toggl.ts` (`durationMismatch`, 60 s) |
| Stored `stop` comes from the End columns when present, else start + Duration; `duration` is always `stop - start` in seconds | One rule everywhere in the app: the fields cannot disagree (the Reports module reads durations from start and stop) | `parseRow` |
| Only unambiguous date formats are read: `YYYY-MM-DD`, `YYYY/MM/DD`, `DD.MM.YYYY`. Others are row errors | `03/04/2025` could be either order, and guessing silently corrupts history. A format sniffed from the whole file is possible later | `parseDate` in `toggl.ts` |
| Comma, semicolon or tab separators are detected from the first line; a BOM, CRLF, quoted newlines and doubled quotes are handled by a small own parser | Spreadsheet programs re-save with other separators; the project avoids new dependencies | `csv.ts` |
| **Idempotency by fingerprint**: `import_id` = `toggl-csv:v1:` + 128-bit hash of start, stop (UTC ISO), trimmed description, lower-cased project and client. Stored on the entry (new optional field in `core/schema.ts` and `architecture.md`); existing `import_id`s in the target space, deleted entries included, are skipped, and so are repeats inside the file | Stable across runs and devices without a server; tags, billable and later edits are left out so they cannot cause re-adds. Not a cryptographic hash, but 128 bits make accidental collisions a non-issue. The version prefix allows a new scheme later | `fingerprint.ts`. To stop treating identical rows in one file as one, add the row number to the key (and accept that re-ordered exports will then duplicate) |
| An imported entry that was **deleted** is not re-imported | Re-importing should not undo a deliberate deletion; deleted records are permanent in this app | Build the `importIds` set from live entries only in `readExisting` |
| Hand-made entries are never matched as duplicates | A near match is a guess, and a wrong skip loses time; a wrong add is easy to delete | Add a start/stop/description match in `buildPlan` |
| Projects match existing ones by name, ignoring case, **within the client** (no client matches only projects without one). Clients match by name. Archived projects still match; deleted ones do not. A client on a row without a project is ignored | The spec; a client exists in the app only through a project. Matching an archived project keeps history together | `buildPlan` in `plan.ts` |
| New projects: `billable: false`, `rate: null`, `currency: USD`, colour cycled from the app palette (duplicated in `run.ts`). Existing projects are never modified | "Billable from the row; rate is not inferred." Importing must not alter existing data. Modules may not import each other, so the palette is repeated | `run.ts` |
| Tags are created as records when missing; entries store the existing spelling | Matches what the time module does | `buildPlan`, `runImport` |
| Entries are written with this device's `device_id`, `created_at` and `updated_at` set to the import time, `task_id: null`, and never a running entry | The spec; Toggl's own creation times are not in the export | `runImport` |
| Import runs in **transactions of 300 entries** with a yield between them, with progress and Cancel. Parsing and planning are also sliced (1000 to 2000 rows). Cancel keeps what was written; re-running adds the rest. The plan is rebuilt when Import is pressed | A 50 000-row file stays responsive (the browser test measures it) and every partial state is a valid, resumable one. Rebuilding avoids creating a project twice after a cancel | `ENTRIES_PER_TRANSACTION` in `run.ts`, `sliceRows` in `plan.ts` and `csv.ts` |
| Parsing stays on the main thread (no worker); files over 100 MB are refused | A worker adds build and CSP surface for a one-time task; 100 MB is far above a multi-year export | `MAX_FILE_BYTES` in `ImportView.tsx` |
| Amounts, tasks, users, colours and other columns are not imported. The preview warns about several users, rows with a Task, and a Duration mismatch | Not part of the record shapes (task_id is a note id); a team export imported as one person's history would be silently wrong | Extend `PlannedEntry` and `runImport` |
| The target space and time zone are chosen on the preview; the space starts as the active one | The spec; the Work and Personal spaces are separate documents with separate fingerprints | `ImportView.tsx` |
| The view is registered as `#/import`, "Import", order 85 (between Backups and Devices), and imports only `core` and `app` | The module contract | `index.ts`, `modules.ts` |
| Browser test generates its large files inside the page and hands them to the file input | Playwright copying 3 MB into the page froze it for half a second, which looked like an app stall | `chooseGenerated` in `scripts/e2e/import.mjs` |
| Not tested against a real Toggl export | None was available. The format is from Toggl's documentation and common knowledge of the export | Add a (redacted) real export under `src/import/fixtures/` and a test |
