# Offline decisions

Decisions made while adding offline support (`src/offline/`), for the owner's review.
The owner-facing description is in `docs/offline.md`.

| Decision | Why | How to change it |
| --- | --- | --- |
| Hand-written worker and a small Vite plugin; no Workbox or vite-plugin-pwa | No new dependencies; the worker is about 100 lines and its rules are unit-tested | Replace `src/offline/` and the plugin in `vite.config.ts` with a library |
| The plugin lists every file Vite wrote (except source maps, `_headers`, `probe-sw.js`) and bundles `src/offline/sw.ts` into `dist/sw.js` with a second, minimal Vite library build | No hand-kept list; the lazily loaded editor chunk is included automatically; the worker can be TypeScript with imports and still be one classic script | `buildManifest` in `precache.ts`, `offlinePlugin` in `build-plugin.ts` |
| The version is the first 12 hex characters of a SHA-256 over every precached file's name and content plus the worker's own source | Changes exactly when something shipped changes; an identical rebuild produces a byte-identical `sw.js`, so it shows no update banner | `buildManifest` in `precache.ts` |
| Both pages and all their files are precached (about 1.1 MB) | `/probe` is small and shares chunks with the app; one rule is simpler than per-page lists | Filter `pages`/`assets` in `buildManifest` |
| Hashed files: cache first, network if missing; nothing is added to the cache at run time | The precache is the whole app; run-time caching would mix versions in one cache | `cacheFirst` in `sw.ts` |
| Page loads: network first, the cached page after 3 seconds, on a network error or on a server error (non-2xx) | Online users always get the newest page; a slow or captive network still opens the app quickly | `NAV_TIMEOUT_MS` in `sw-logic.ts`, `networkFirst` in `sw.ts` |
| The cached page is the one from the worker's own build; a page fetched online is never written to the cache | A newer page in an older cache would reference files that are not cached, and break offline | — |
| Never answered by the worker: non-GET, cross-origin (ntfy, GitHub API), `/signal/*`, `/probe/*`, `sw.js`, `probe-sw.js`, URLs with a query string for files, and unknown paths | The relay and other services must always see real network requests; the probe's own test worker at `/probe/` must stay independent | `NEVER_PREFIXES`, `NEVER_FILES` and `routeRequest` in `sw-logic.ts` |
| The app's worker has scope `/` and therefore also serves `/probe` | They then open offline too; the probe registers its own worker at the narrower scope `/probe/`, which wins for that path, and the browser test checks its card still passes | Skip `probe` in `routeRequest` |
| A new version waits; the banner's **Reload** sends `SKIP_WAITING`, and every tab reloads once when the new worker takes over (`controllerchange`) | Code and cached files always match; a tab left on old code could ask for a lazy file the new cache no longer has | `client.ts`; to keep other tabs open, show the banner instead of reloading in the `controllerchange` handler |
| The first install takes control at once (`clients.claim()`) without reloading | Offline works after the very first visit, not only after a second load | Remove `claim()` from `cleanup` in `sw.ts` |
| Open tabs check for a new `sw.js` on load, on returning to the tab, on reconnecting, and hourly | A tab left open for days still learns about a deploy | `UPDATE_CHECK_MS` in `client.ts` |
| If the new worker has not taken over 4 seconds after **Reload**, the page reloads anyway | The banner must never leave the user stuck | `RELOAD_FALLBACK_MS` in `client.ts` |
| Kill switch: `APP_OFFLINE=off` (or the `OFFLINE` line in `vite.config.ts`) builds `sw-kill.ts` as `sw.js` and makes the app unregister its own registration | Recovery from a bad worker without touching each device; the switch is in the repo, not a hand-edited file on the host | `sw-kill.ts`, `vite.config.ts` |
| `Cache-Control: no-cache` for `/sw.js` and the HTML pages in `public/_headers`; the Content-Security-Policy is unchanged | The browser and Cloudflare must revalidate them so updates are seen; the worker loads from `'self'`, which `worker-src` and `connect-src` already allow | `public/_headers` |
| Cache names start with `app-precache-` (the generic storage prefix) and only those are deleted on activate | A rename of the app does not orphan caches; any other cache on the origin is left alone | `CACHE_PREFIX` in `sw-logic.ts` |
| The Offline label reads `navigator.onLine` | It is a hint only ("no network at all"); the app never depends on it | `useOnline` in `src/app/hooks.ts` |
| Service-worker types are declared locally (`sw-types.ts`) instead of using the WebWorker library | The project compiles against the DOM library and the two clash | Give `src/offline/sw*.ts` its own `tsconfig.json` |
| Installable app: `manifest.webmanifest` is generated at build from `APP_NAME`; standalone, relative `start_url`/`scope`, 192/512 PNG icons (one maskable-safe image) rendered from `scripts/icons/app-icon.svg`, `launch_handler: focus-existing` | Without a manifest Firefox/Chrome on Android make a plain shortcut that opens a new tab each tap; with one they install a real app that refocuses its window. Firefox ignores `launch_handler` and has no desktop PWA install | `buildWebManifest` in `src/pwa/manifest.ts`, `node scripts/make-icons.mjs` |
| The precache lists every file in `dist/` (including those copied from `public/`), not only Vite's bundle | The manifest and icons must work offline for install and launch | `walk` in `build-plugin.ts` |
| The update banner asks the waiting version whether to back up first: `src/offline/update-meta.json` (`backupFirst`) is read by the build plugin into the manifest, the worker answers `GET_VERSION` with `{ version, backupFirst }`, and the running page shows "Make a backup before reloading" with a link to Backups | The warning must come from the build people are running, which is why this ships before a release that moves data; a version that does not answer counts as no | Set `backupFirst` in `update-meta.json` for the release that needs it, and back to `false` after |
