# Reports module decisions (branch `feat/reports`)

Choices made while building `src/reports/` without the owner present.
Each says what was chosen, why, and how to change it.

| # | Decision | Why | To change it |
| --- | --- | --- | --- |
| R1 | **Plain TypeScript aggregation** in `aggregate.ts`, `dates.ts`, `format.ts` and `export.ts`, with no Yjs or DOM inside | The design plan says DuckDB-Wasm only if needed; a month of entries is tiny. Plain functions are unit-tested directly, including time zones | Replace `buildReport` with a query layer; the views only consume the `Report` shape |
| R2 | **The module reads the documents itself** (`source.ts`) instead of using the time module | Modules must not import each other; the record shapes in `architecture.md` are the contract. Every field is read defensively | If the record shapes change, update `source.ts` and its test only |
| R3 | **Durations come from `start` and `stop`**, not from the stored `duration` field; a running entry counts up to now | One rule for running and stopped entries, and the two fields cannot disagree. A stop before the start counts as zero | Switch `resolveEntries` to use `duration` for stopped entries |
| R4 | **Days are local calendar days** and entries are cut at local midnight, so a day can have 23 or 25 hours on a daylight-saving change | Matches what the person sees on the clock; tested in Berlin and New York | Pass a fixed zone into `dates.ts` if a "report in another time zone" option is ever wanted |
| R5 | **Ranges are half-open and entries are clipped to them**; the Detailed view shows one row per whole entry but with only the time inside the range | Summary, Weekly and Detailed totals always agree | Show the full duration in Detailed and mark clipped rows |
| R6 | **Weeks start on Monday**; the shared setting `settings.week_start = sunday` switches it | Project default; the setting already exists in `architecture.md` | Read another value in `readWeekStart` |
| R7 | **An entry with several tags counts toward each tag** and the UI says so; percentages are always shares of the report total | Matches Toggl; the alternative (splitting the time) hides tags | Split the duration by the number of tags in `bucketsOf` |
| R8 | **Amounts use the entry's `billable` flag and the project's `rate`**, per currency; no rate means no amount (a rate of `0` gives a zero amount). The project's own `billable` flag is not consulted | The entry flag is what the person set per entry, as in Toggl. Mixed currencies are never added together | Also require `project.billable` in `entryAmount` |
| R9 | **Archived and deleted projects keep their hours** and are labelled "(archived)" or "(deleted)"; an unknown project id shows "(Unknown project)" | Worked hours must not vanish from reports when a project is archived | Filter them out in `resolveEntries` |
| R10 | **Filters are single choices** (one client, project or tag, billable state, description text) | Covers the owner's request with simple controls that work at 375 px; multi-select needs a custom widget | Make the `Filters` fields arrays; `applyFilters` is the only place that reads them |
| R11 | **"This space" or "All spaces"**; in all-spaces mode project and client labels get the space name and are never merged across spaces | Same names in two spaces are different records | Merge by name in `projectDisplay` and the project key |
| R12 | **Hand-drawn SVG bar chart**, stacked billable and not billable, with day, week or month bars depending on the range length (up to 62 days, up to 210 days, then months) and a data table under it for screen readers | No chart library, CSP-safe (classes, no inline `style`), accessible. A full year would otherwise have 365 unreadable bars | Change `granularityFor` |
| R13 | **Hours format follows `settings.hours_format`** in the Personal document (`decimal` default, `hm`; the older `h:mm` still reads as `hm`); it is changed only on the Settings page | One setting for the whole app, synced across devices | See `docs/decisions/settings.md` |
| R14 | **h:mm rounds to the nearest minute per figure**, so figures in one table may not add up to the displayed total by a minute | Rounding the underlying milliseconds would hide real time | Show seconds in `formatDuration` |
| R15 | **CSV is export only**, in the Detailed order of time, with a byte-order mark for spreadsheet programs. Text starting with `=`, `+`, `-`, `@`, tab or carriage return gets a leading apostrophe | Prevents spreadsheet formula injection from a description. CSV is never read back | Drop the apostrophe rule in `csvField` if exact text matters more |
| R16 | **Copy as Markdown** copies a summary list and table for the chosen grouping; when the browser refuses clipboard access the text is shown in a text box to copy by hand | The clipboard API needs permission in some browsers and contexts | — |
| R17 | **Test hook `window.__reports` behind `?test`**, installed by the Reports view, seeds records through the real record shapes | The browser test needs records without the time module | Delete `testhook.ts` once the time module offers a seed path |
| R18 | **Weekly view shows up to 62 days** and rows can be grouped by project, client, tag or description | The grid is unreadable beyond that; Group by already exists for the other views | Raise `MAX_DAYS` in `WeeklyView` |
| R19 | **One Reports page** replaces the Summary, Detailed and Weekly tabs. Order: filters, totals, chart (foldable), one table, entries (foldable, sortable). Filters, Group by and Then by apply to every section | Tabs under the filters read like facets of one report; a single page shows every number once | `ReportsView.tsx` |
| R20 | **The table has a row per group, hours per column, total, share and amount.** Columns are days, weeks or months by the chart's rule (R12), so the 62-day cap of the old Weekly grid is gone. Cells are aligned with the chart buckets (`Group.cells`) | One table instead of a breakdown and a grid; long ranges stay readable | `ReportTable.tsx`, `columnIndex` in `aggregate.ts` |
| R21 | **Chart folded or open, entries folded or open: remembered per device** in `localStorage` (`app-reports-folds`); chart defaults open, entries closed. The table is never folded | A per-device view preference, not shared state; entries are the longest section | `useFold` in `ReportsView.tsx` |
| R22 | **Export per section:** Copy as Markdown on the table, Download CSV on the entries. Old links `#/reports/detailed` and `#/reports/weekly` open the page at that section (detailed also opens it) | Each export sits with the data it exports; old bookmarks keep working | `sectionFrom` in `ReportsView.tsx` |
| R23 | **Page cleanup (#135):** the filter form is collapsed into one line ("This week · All spaces · By project · 2 filters") at the top that opens every control; the totals follow at once. Chart, the chart's data table, Entries and the filter line share one collapsible style (`Disclosure`: chevron button, actions while open). Only the chart and entries folds are remembered (R21); the filters start collapsed on every visit | Nine dropdowns sat before any result; three folds looked different | `Disclosure` in `parts.tsx`, `controlsLine` in `ReportsView.tsx` |
| R251 | **Narrow table (#251):** the first column is sticky, at most 11rem (7.5rem on phones); names truncate with "…" and carry the full label in `title`; in all-spaces reports the space name is a muted second line. `Group.space` / `ResolvedEntry.projectSpace` carry it; `label` still ends with " · space", so filters, Entries and exports are unchanged | Long billing codes filled the row and pushed the days off screen; the cut-off next day column and the edge shading are the cue that it scrolls | `NameCell` in `ReportTable.tsx`, `reports.css` |
| R-335 | **Reports is a segment of the Timer page** (List \| Week \| Reports at `#/timer/reports`); the Reports tab is gone, the tab row is Timer, Notes, Tasks, Settings and the freed slot stays empty. `#/reports[/<section>]` redirects to `#/timer/reports[/<section>]` (R22 sections kept). The shell owns the switch: a view registers `joins: 'timer'` (and the page its `modes`), `TimerPageHeader` draws the segments, `App.tsx` routes them, so `time` and `reports` never import each other. Hiding Reports (Features) removes the segment and sends `#/timer/reports` to `#/timer`. No timer bar on Reports (the header timer covers it, X17). Supersedes the tab list in F14 | Fewer tabs on a phone (F14); Reports is where the week is read, one tap from the list. Option A of #335: Week keeps editing entries, Reports stays read-only | `registry.ts` (`joins`, `modes`), `nav.ts` (`legacyRoute`), `features.ts` (`hiddenRoute`), `views/TimerPageHeader.tsx` |
| R-335b | **Previous / Next period (#277).** Step by the period's own length: a whole calendar month or year to the neighbouring month or year, anything else (day, week of either start, custom) by its length in calendar days. Stepping from a preset gives the preset again when it matches (This week, Previous = Last week). **Next is disabled when the period ends today or later** (it never walks into the future). Labels "Previous period" / "Next period"; the range is shown as dates beside them. Keyboard shortcuts stay a follow-up | Calendar math through `dates.ts` keeps DST and month lengths with the platform; a week never drifts off its week start | `stepRange`, `canStepNext`, `presetFor` in `dates.ts` |
| R-335c | **The view and the range are remembered per device** (`timer-view` holds `list`, `week` or `reports`; `app-reports-range` holds preset and custom dates), UI-only in `localStorage`. A bare `#/timer` opens the remembered view. A range other than This week shows its label as a filled pill with a "This week ×" button beside it. **One space filter** (`app-space-filter`, `src/app/space-filter.tsx`) serves List, Week, Reports and Organize; Reports' own "This space / All spaces" is gone | The last view should come back; a stale range must not look like the current week; two space controls disagreed | `ReportsView.tsx`, `timer-views.ts` |
